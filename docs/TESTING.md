# Chrome 手动验收

## 真实 API 自检

在栖签「设置与偏好 → 运行 Chrome 自检 → 开始自检」运行 12 项业务检查及 1 项清理检查：持久化、目录改名、归档与固定标签、去重、恢复窗口、锁定、排序、跨组状态、回收站、备份、原生标签组、危险导入及清理。

测试使用独立窗口和带唯一标记的临时书签目录。报告保存于本地，重开页面可查看及下载 JSON。它不等于双电脑同步验收。

2026-09-21：用户在已加载的 Chrome 扩展中运行自检并确认全部通过（12 项业务检查及 1 项清理检查）。结果来自用户反馈，未收取 JSON 报告；双电脑同步与其他手动场景仍待验证。

## 逐项验收

使用专门的测试窗口与无敏感信息的页面，避免在实际工作窗口首次试用。

1. 构建并加载 `dist`，查看扩展详情有无错误；打开 service worker 查看启动日志。
2. 新开三个 HTTP(S) 标签，固定其中一个。点击扩展图标，验证两个归档、固定标签保持打开、管理页出现两个真实书签。
3. 打开 Chrome 书签管理器，确认 BetterTab / 时间组 / 实际链接及元信息书签。
4. 分别测试「当前、选中、左侧、右侧、其他、所有窗口」。验证其他窗口的未选择标签不受影响。
5. 打开已归档的重复地址再归档：默认跳过重复地址且保持该标签打开。
6. 恢复单条、组、新窗口；验证默认移除、保留选项，以及锁定组始终保留。
7. 建立原生 Chrome 标签组，设置名称和颜色，归档再恢复检查分组。
8. 测试组菜单重命名、锁定、星标、笔记、分类；逐条星标与任务循环。
9. 拖标签排序、跨组移动、拖底部创建组；拖组到组把手排序，拖到标题合并链接。
10. 多选移动、复制、删除、恢复。删除应进入回收站，可移回；永久删除先确认测试内容。
11. 用 OneTab 导出文本导入，确认空行边界和含竖线标题。测试 javascript URL 拒绝且没有部分导入。
12. 导出文本和 HTML，用文件编辑器检查内容；HTML 标题特殊字符不应成为脚本。
13. 在设置开启工具栏快捷面板，检查快捷列表和完整管理页入口。
14. 用 `/` 与 `bt + 空格` 搜索，用扩展快捷键打开、归档。
15. 关闭并重新打开 Chrome，确认数据与元信息仍在。手工改书签标题，管理页应自动刷新。

## 双电脑

1. 两台 Chrome 登录同一测试账号并开启书签同步，各加载同一构建目录。
2. A 归档，等待 B 的 Chrome 书签页收到目录；B 打开栖签，应出现真实链接与组信息。
3. A 修改组名、笔记、任务、锁定；等待后 B 验证。B 移动一个条目，再到 A 验证。
4. A 暂时离线，新增归档，恢复网络后验证。记录 Chrome 实际同步时间，不以 UI 写入成功当作远端确认。
5. 分别验证本地目录与账号目录标识。若本地目录不进入账号同步，将整个目录移至账号书签再验证。
6. 同时改同一组笔记并观察 Chrome 冲突处理；检查网址仍存在，不宣称实现了自有冲突合并。

## 自动化

`npm test` 使用 Vitest 与内存 Chrome API 模型。重点验证数据不丢失；并不模拟真实跨设备同步或真实 service worker 生命周期。
