# OneTab 功能对标清单

调研日期：2026-09-20。此文件先于业务实现建立。目标：Chrome Manifest V3 扩展 BetterTab，以 Chrome 书签为归档的唯一事实来源，并提供可选择的组件库界面。

## 资料与核对边界

- [OneTab 官网](https://www.one-tab.com/)：归档、恢复、导入导出、分享，以及新版文件夹、任务、笔记。
- [官方帮助](https://www.one-tab.com/help)：拖拽、多选、快捷列表、搜索、地址栏、快捷键、隐身模式、加密同步。
- [官方共享页面示例](https://www.one-tab.com/page/d5D-_oT5QYOJt_F4spUCTg)：公开页面、二维码、复制链接。
- [Chrome bookmarks API](https://developer.chrome.com/docs/extensions/reference/api/bookmarks)：目录、事件、设备内 ID、syncing 属性。
- [Chrome 登录与同步说明](https://support.google.com/chrome/answer/185277)。

官方网页不是完整的版本化产品规格，未安装检查 OneTab 每一个选项，因此下面区分「官方公开确认」与「兼容性目标，细节待实测」。不把旧版经验冒充最新版全部行为。以下为独立需求设计，不复制 OneTab 源码、商标或素材。

## 数据与同步设计

1. `BetterTab` 专用文件夹下，每个归档组是普通文件夹，标签是实际 URL 书签。普通 Chrome 书签管理器也可以打开归档。
2. 优先在 `syncing=true` 的账号书签目录创建根目录，否则明确显示本地状态。扩展不获取 Google 凭据、不承诺同步时延。两个电脑都需安装扩展并开启同账号书签同步。
3. 书签节点 ID 只在设备内有效，不作为跨设备全局身份。组内元信息使用保留标记书签记录版本、随机 UUID、时间、锁定、星标、笔记、分类、条目状态和原生标签组信息。元信息不指向扩展 ID，避免不同安装 ID 失效。
4. 使用单个后台写入队列，按条目增量修改。先写书签再关闭标签，失败时留住未确认保存的标签。重复项跳过时不关闭；页面已经导航时不关闭。
5. 监听书签新增、变更、移动、删除、重排及导入结束。多个同名根目录全部读取，不自动删库或合并；支持用户从书签页手动整理。
6. Chrome 不提供跨设备事务、同步完成回执或冲突解决 API。同时修改同一组元信息仍可能遵循浏览器的冲突处理，需实机测试。UI 不能将“写入成功”显示为“所有设备同步完成”。
7. 回收站也在专用书签目录内。删除为移动，清空回收站才永久删除。元信息被用户删除时，实际链接仍可正常读取。
8. 默认不收集遥测、不请求外部 favicon，不上传链接到自建服务器。导入拒绝 javascript/data 等可执行地址。离线分享 HTML 必须转义标题和 URL。

## 分阶段交付与明确差异

- 首先完成这份清单，再实现归档、恢复、书签存储、基础组织以及两个可交互的 UI 样例。
- 用户选择视觉方案后可移除另一套组件依赖。
- 公开分享 URL、二维码和撤回分享需要托管服务；本地 HTML 导出只能作为离线分享，不冒充公网发布。
- 不实现 OneTab 私有账号、付费许可或其加密云协议。书签同步是本项目指定的替代设计，不具有同样的端到端加密保证。
- 具体完成情况记录在 `docs/IMPLEMENTATION-STATUS.md`，保留未完成项及实机验收项。
