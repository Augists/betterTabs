## 已验证

- `npm run build`：TypeScript 类型检查、Vite 前端打包及 Manifest V3 worker 打包通过。
- `npm test`：书签及导入导出核心逻辑的自动化测试通过，数量以最新测试输出为准。
- 早期内置浏览器曾验证页面加载、搜索、建组、分类、笔记及文本导入；0.3.0 的跨浏览器界面截图和视觉回归仍需完成。
- 样例数据与真实扩展存储完全分离，样例不操作用户标签。

## 发布前必须验收

- 0.3.0 在 Chrome、Edge、Firefox 重新加载及自检；0.1.0 的真实 API 自检由用户反馈全部通过。
- 双电脑、同账号，新增、重命名、排序、任务、笔记、锁定、删除同步。
- 从离线恢复、同时编辑、账号书签和本地书签切换、重复根目录、批量数千标签。
- 隐身模式、文件 URL 权限、原生组恢复、弹窗和跨窗口焦点。
- 移动端窄屏及完整键盘拖拽替代流程；当前已有响应式 CSS，但没有完成多设备视觉回归。

## 已知约束

1. Chrome 不提供跨设备原子事务。当前本机写操作串行，不会整库覆盖；两台机器同时改同一组元信息仍可能覆盖彼此的状态。
2. 元信息以 URL 为条目键；禁用去重后，同组同 URL 的任务/星标共享。原生组同 URL 重复也有同类限制。
3. 归档写入失败会保留部分书签和所有源标签；再次归档的去重会跳过已写的地址。这样偏向保留数据，但需要用户整理部分保存组。
4. 恢复批量中途失败可能已有部分新标签打开；所有归档保留以避免丢失，用户可能需要去重。
5. 恢复组最后一条后保留空组，用于保留笔记；不自动删除空组。
6. Chrome 内部页面、扩展页面以及 javascript/data URL 不归档；HTTP(S)、FTP、file 可归档，file 恢复受 Chrome 权限限制。
7. 根目录通过专用标记识别，改名后仍可读取，兼容旧版同名根目录。根目录直接放置的书签不作为组展示，应放进子文件夹。
8. 2026-09-21 用户确认扩展内真实 API 自检全部通过（含清理共 13 项），未收取 JSON 报告。双电脑同步、完整界面交互及其他手动场景仍待验收。

以上差异意味着当前不能宣称已 100% 复刻 OneTab。后续应根据用户选择的界面与对标版本继续收敛。

## 0.3.0 跨浏览器状态

Chrome/Edge 使用 Manifest V3 service worker；Firefox 使用 Manifest V3 background scripts，最低 Firefox 142。40 项原测试加 Edge 收藏夹入口测试，共 41 项通过。Firefox 156 临时安装和 Edge 临时启动已完成；三个浏览器在 0.3.0 上的完整 UI、自检与双设备同步尚未验收。Firefox 未签名 ZIP 不能长期安装；需 Mozilla unlisted 签名 XPI。Chrome、Edge、Firefox 的账号书签不会跨厂商自动同步，JSON 完整备份可用于迁移。GitHub v0.3.0 是预发布。
